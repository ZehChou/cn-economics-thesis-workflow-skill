## 附录 D：通用规则与注意事项

### D.1 阶段间变量传递

状态通过 `.thesis_state.json` 持久化，在启动时由 AI 读取恢复：

| 字段 | 类型 | 设定阶段 | 用途 |
|------|------|----------|------|
| `user_level` | `"L1"` / `"L2"` / `"L3"` | Phase 0（Step 0.5） | 全程自适应 |
| `analysis_backend` | `"python"` / `"stata"` | Phase 0（Step 0.1） | Phase 4-8 取附录 H 还是 I |
| `current_phase` | `int` | 各 Phase 完成时 | 断点续传 |
| `model_framework` | `object` | Phase 5 | Phase 6-8 继承 |
| `data_path` | `string` | Phase 3 | 后续继承 |
| `citation_db` | `object` | Phase 1-2 | Phase 9 引用替换 |
| `variables` | `object` | Phase 3 | Y/X/controls/mechanism 列表 |
| `hypotheses` | `object` | Phase 2 | H1-H3 |
| `thesis_outline` | `object` | Phase 9.3 | 正文撰写继承 |

### D.2 错误处理

| 错误场景 | 处理方式 |
|----------|----------|
| **分析脚本报错（后端 B · Python）** | 读完整 traceback，定位到具体行与列名；常见：包未装、列名不存在、dtype 不符（字符串当数值）、公式写错 |
| **分析脚本报错（后端 A · Stata）** | 读日志定位；常见：包缺失、路径错、变量名不匹配、`$controls` 未定义被静默展开为空 |
| **`$controls` 宏为空导致回归"运行成功但结果错误"** | 每个 do file 头部显式定义；跑前先 `display "$controls"` 验证非空 |
| **pyfixest / linearmodels 接口报 `AttributeError`** | 版本漂移。先 `dir(pf)` 查实际接口，按实际改并回填附录 H（附录 H.0 有自检脚本） |
| **数据读取错误** | 检查路径、格式、编码；`.dta` 用 `pd.read_stata`，中文列名统一 UTF-8 |
| **文献 PDF 不可读** | 提示用户检查是否为文字版，建议 OCR 预处理（附录 J.4） |
| **python-docx 渲染异常** | 降级为文本占位，提示用户手动修复 |
| **MCP 连接失败（仅后端 A）** | 重新运行 `uvx stata-mcp doctor` 诊断 |
| **CNKI/学术数据库无法直接访问**（需登录/验证码/无公开 API） | 走 L1 Zotero 抓取或 L2 人工检索（附录 J.3） |
| **文献 API 限流（OpenAlex 429 / S2 429）** | 指数退避重试；改用另一个源（Crossref / S2 / 作者主页）；检查 API Key 与 credits |
| **文献 PDF 为扫描版、文本抽取失败** | 提示用户 OCR（Tesseract/Adobe）或提供图片版由视觉模型识别 |
| **中文乱码 / 编码不一致** | 统一 UTF-8 读写；CSV 输出加 `utf-8-sig` |
| **同一错误连续失败 2 次** | 暂停自动重试，把 traceback/日志交给用户，请其确认数据结构与运行环境 |

### D.3 L1 新手 mini 教学原则

- 每个核心概念用一句话解释 + 一个类比
- 示例：什么是固定效应？"固定效应就像给每个个体配一个专属截距，控制那些不随时间变化的个体特征（比如管理能力）"
- 用户反问再深入，不应单向灌输
- 默认选项标注为"推荐"
- 所有代码操作分步说明做了什么

### D.4 时间估计

| Phase | 预估耗时 | 用户参与度 |
|-------|----------|-----------|
| Phase 0 | 10-20 min | 低（给数据路径 + 选后端，回车即默认） |
| Phase 1 | 1-2 小时 | 低（回答选题问题） |
| Phase 2 | 2-3 小时 | 中（Zotero 抓一轮全文，其余 AI 做） |
| Phase 3 | 1-2 小时 | 低（确认变量清单） |
| Phase 4 | 1-2 小时 | 低（AI 自动运行+解读） |
| Phase 5 | 2-4 小时 | 中（选识别策略 + 确认模型框架） |
| Phase 6 | 1-2 小时 | 低（选 2-3 项检验） |
| Phase 7 | 1-2 小时 | 低（AI 自动运行+解读） |
| Phase 8 | 1 小时 | 低（选 2-3 个维度） |
| Phase 9 | 3-6 小时 | 中（确认大纲 + 审阅终稿） |

**总预估**：12-24 小时，其中用户实际操作时间约 2-4 小时（其余是 AI 运行与等待）。
真正的耗时变量是**数据就绪程度**与**文献全文获取速度**，不是写作。

### D.5 研究诚信红灯清单（High-risk blacklist）

以下行为**禁止**执行；任何一条被触发都应停下来向用户说明，而不是静默继续（对应 Phase 4.5 / 6 的透明化纪律）：

| # | 🚫 禁止行为 | 为什么 | 替代做法 |
|---|------------|--------|----------|
| 1 | 仅为达到 p<0.05 而更换 Y/X 度量、样本区间、控制变量集或聚类层（无理由的规格搜索） | 多重比较下的虚假显著（p-hacking） | 先给理论与数据威胁的理由；每轮尝试写入 spec 日志并全量披露（Phase 4.5） |
| 2 | 事后依据估计结果选择“显著的一组”，再补充异质性理由 | data-driven 分组等于捏造结论 | 异质性维度须在 Phase 2/8 预先指定并有文献/理论依据（Phase 8 规范） |
| 3 | 编造或篡改数据、回归系数、标准误或参考文献 | 学术不端，无法复现 | 所有数字来自分析脚本输出；无法复现的系数不得写入论文 |
| 4 | 只报告“好看”的稳健性结果，隐藏失败的规格 | cherry-picking 破坏可信度 | 主文报告预定义检验；全部尝试（含不显著的）放附录或 spec 日志 |
| 5 | 用 OLS/单一时点相关直接声称因果，不讨论识别假设 | 识别假设才是因果断言的依据 | 内生性来源诊断（Phase 5）+ 证据强度分级表述 |
| 6 | 跨阶段更换数据集或变量口径，却不更新 `.thesis_state.json` 与复现脚本 | 复现断裂、阶段结果不可比 | 变更前记录理由与版本；模型框架锁定机制（Phase 5） |
| 7 | 以 python-docx 等错误工具“精读 PDF”，或伪造精读/引用记录 | 工具链错误 + 虚假文献工作 | pypdf/pdfplumber + OCR（Phase 2）；引用信息以真实 PDF 为准 |
| 8 | 随机过程（安慰剂/Bootstrap/PSM 抽样）不设随机种子且不记录 | 结果不可复现 | 后端 B 固定 `SEED`（附录 H.1）；后端 A 在 do-file 头部 `set seed`（附录 F.1） |
| 9 | 为使脚本"运行成功"而静默 `dropna()` / `drop if` / 改写变量，导致样本量与正文不符 | 结果与描述统计对不上，复现断裂 | 任何行数变动必须打印并留痕；样本筛选只能作为显式规格并登记 |

**触发场景**：AI 每次准备“换一种规格再跑一次”前，先对照本表；命中任一 → 停止并先向用户解释动机与记录方式。
