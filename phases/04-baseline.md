## Phase 4：基准回归

> 本阶段遵循主 Skill 中定义的**通用交互模式：计量分析流程**（方法推荐 → 用户确认 → 检查变量就绪 → 写分析脚本并运行 → 结果解读 → 迭代）。

### Step 4.1：方法推荐

AI 基于数据结构推荐基准回归策略：

| 数据结构 | 推荐方法 | 说明 |
|----------|----------|------|
| 截面数据 | OLS | 线性回归，异方差稳健标准误 |
| 面板数据 | 固定效应 (FE) / 随机效应 (RE) | Hausman 检验决定 |
| 二值因变量 | Logit / Probit | 报告边际效应 |
| 计数数据 | Poisson / 负二项 | |
| 多期面板 | 双向固定效应 (TWFE) | 个体+时间固定效应 |

L1 用户：AI 简要解释所选方法的适用性
L2/L3 用户：AI 同时讨论模型假设和识别条件

### Step 4.2：模型设定说明

在写分析脚本之前，AI 先向用户说明完整模型设定：

```
模型设定
═══════════════════════════════════════

Y_it = α + β*X_it + γ*Controls_it + μ_i + λ_t + ε_it

• β 是核心估计量，预期方向：{正/负}
• 控制变量已包含：{控制变量列表}
• 个体固定效应 μ_i：控制不随时间变化的不可观测因素
• 时间固定效应 λ_t：控制年度宏观冲击
• 标准误在 {个体/年份} 层面聚类

回归序列：
  (1) 仅 X：Y = α + β*X
  (2) 加入控制变量
  (3) 加入固定效应
  (4) 完整模型（最终基准）

输出：回归系数表（output/tables/baseline.rtf）、各模型 R²、F 统计量
```

### Step 4.3：写分析脚本并运行

> **代码不在本文件**。按 `analysis_backend` 取对应附录的可运行模板：
>
> | 后端 | 代码位置 | 脚本名 |
> |---|---|---|
> | B · Python（默认） | **附录 H.2** | `scripts/02_baseline.py` |
> | A · Stata（可选） | **附录 I.3** | `do/02-baseline.do` |
>
> 两个模板产出同一张四列基准表（(1) 仅 X → (4) 完整模型），列序与下方"表格形态"一致。

**表格形态（后端无关，Phase 9 直接按此排版）**

```
表 5-x  基准回归结果
─────────────────────────────────────────────
变量            (1)      (2)      (3)      (4)
X              β        β        β        β
              (se)     (se)     (se)     (se)
控制变量        否       是       是       是
个体固定效应     否       否       是       是
年份固定效应     否       否       是       是
行业×年份FE     否       否       否       是
N              n        n        n        n
R²            r2       r2       r2       r2
─────────────────────────────────────────────
注：括号内为标准误；*** p<0.01, ** p<0.05, * p<0.1；(3)(4) 列标准误聚类到个体。
```

**运行前自检（防止静默错误）**

```
□ 控制变量列表来自 .thesis_state.json，不是凭记忆写的
□ 固定效应与聚类层级在模型设定说明（Step 4.2）中已对用户讲清
□ 含随机过程的脚本已固定随机种子（附录 D.5 第 8 条）
□ 每个跑过的规格写入 log/spec-search.csv
```

> 🛟 失败分支：脚本报错 → 读完整错误栈定位（包未装 / 列名不存在 / 数据类型 / 公式写错最常见），
> 修复后重试；**同一错误连续失败 2 次** → 暂停，把报错原文与涉及的列交给用户，请其确认数据结构。
> 详细错误处理见附录 D.2。

### Step 4.4：结果解读（含经济显著性）

```
基准回归结果解读
═══════════════════════════════════════

1. 统计显著性
   • 核心变量 X 系数 β = {value}，在 {p-value} 水平上显著
   • 与预期方向 {一致/不一致}

2. 经济显著性（关键！）
   • X 一个标准差的变化 → Y 变化 {effect_size} 个标准差
   • 相当于 Y 均值的 {percent}%
   • 与已有文献的效应量对比：{大于/小于/相似于} 同类研究
   • 经济显著性判断：{效应量足够大/效应量偏小但方向稳健}

3. 控制变量
   • {控制变量1}：{显著方向和经济含义}
   • {控制变量2}：{显著方向和经济含义}

4. 模型拟合度
   • R² = {value}，F 统计量显著
   • 说明模型解释了 Y 变异的 {percent}

5. 检查点
   □ 系数方向与理论预期一致
   □ 核心系数在统计上显著
   □ 核心系数在经济上显著（效应量足够大）
   ☐ p > 0.1 或经济显著性弱时：AI 应推荐改善方案
```

### Step 4.5：显著性改善方案

> 🔴 **研究诚信红线（详见附录 D.5）**：下述菜单用于诊断**设定问题**，不是“调到显著为止”的工具。
> 更换 Y/X 度量、样本区间、固定效应或聚类层，必须先用理论与数据威胁给出理由；
> 每一轮尝试写入 `log/spec-search.csv`（规格、系数、SE、p 值、是否采纳、理由），
> 论文定稿时**全量披露**已尝试规格（正文报告最终选择，其余列于附录或脚注）。

若核心变量 p > 0.1 或经济显著性偏弱，AI 按优先级推荐以下方案：

```
建议改善方案：
1. 检查数据量是否充足 → {样本量是否够}
2. 检查变量定义 → {是否有测量误差}
3. 考虑更高维固定效应 → {如行业×年份 FE}
4. 考虑更优标准误聚类 → {如行业层面聚类}
5. 检查离群值影响 → {缩尾处理}
6. 考虑非线性效应 → {引入平方项}
7. 更换估计方法 → {更换为更适合的方法}

请选择要尝试的方案（可多选）：A / B / C / ...
```

用户选择后，AI 更新分析脚本重新运行，并把这轮规格写入 spec-search 日志；若多轮尝试后仍不理想，转 Phase 5 内生性诊断，避免无记录的无限规格搜索。
